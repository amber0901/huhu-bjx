## 缓存与更新

旧版媒体只缓存 5 分钟，缺少条件校验，重复配乐地址也不同。本轮采用：

1. `public/media/<完整 SHA-256>.<扩展名>`：文件变化即得到新地址；相同配乐只用同一地址。
2. 媒体响应设置 `Cache-Control: public, max-age=31536000, immutable`，并提供强 ETag。
3. 页面、脚本和样式使用 `no-cache` + ETag，未变更时返回 304；新部署可获取新页面和新素材地址，避免一直显示旧版本。
4. HTTPS／localhost 环境额外启用 Service Worker，将当前清单中的 10 个去重素材保存在 CacheStorage；从完整缓存响应生成正确的音频 Range 206 响应，支持拖动进度与重听。
5. 新素材全部缓存成功后清理失效缓存。缓存失败不阻塞课堂页面，仍可回退到浏览器 HTTP 缓存及网络。

浏览器实际验证：第一次显示“本机素材已缓存 10/10（本次直接复用 0 个）”；重新加载后显示“本机素材已缓存 10/10（本次直接复用 10 个）”。证明图见 [缓存复用](qa/cache-reuse-v3.jpg)、[新版首页](qa/baijiaxing-home-v3.jpg)、[诗词页](qa/baijiaxing-li-v3.jpg)。缓存状态只在老师面板中显示。

普通公网 HTTP IP 地址不能启用 Service Worker，此时长期 HTTP 缓存仍生效。首次使用、新版本素材、浏览器清空缓存或存储被回收时仍需下载；不承诺永不联网。手写识别仍需联网调用模型。识别请求、笔迹图片、口令、会话及 API 响应不写入素材缓存。

缓存实现依据：[MDN HTTP caching](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)、[Cache-Control](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control)、[Using Service Workers](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)。

## 制作与部署

在素材制作电脑安装 `cwebp` 后，发布原始素材，再从工作区根目录执行：

```sh
python3 material-workshop/scripts/optimize_runtime_assets.py
cd surname-poetry
npm run check:assets
npm test
```

压缩脚本只在制作电脑运行。生成的 `public/media/`、`public/home-background.css`、`data/runtime-assets.json` 随部署代码一起提交 Git。Docker 直接使用准备好的文件，不依赖素材制作目录、cwebp 或生成服务密钥。

`check:assets` 会核对原始文件、派生文件和内容哈希；Dockerfile 也在构建时运行此检查。素材变更后若忘记更新派生资源，检查会失败，避免把旧缓存版本随新素材上线。运行时清单在进程中复用，部署更新应重建并重启容器。
